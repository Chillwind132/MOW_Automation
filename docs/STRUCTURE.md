# Structure and maintenance

Current documentation: [start here](INDEX.md).

The supported entry point is the project-root `headless_host.py`. It forwards to
`headless/headless_host.py`, which resolves `data/` and `validation/` from the project
root, independently of PowerShell's working directory. The Frida bridge and GM
prompt live beside their Python modules in `headless/`.

## Where new work belongs

- Put host orchestration and review code in `headless/`.
- Put shared live observation and final replay processing in `modules/live_game_data/`
  and `modules/end_game_results/`; see [module contracts](MODULES.md).
- Put optional diagnostics and controlled experiments in `diagnostics/`; direct
  scripts import `_bootstrap` to locate the active host modules.
- Put regression tests in `tests/` and captured inputs in `tests/fixtures/`.
  Tests import `_test_paths` so direct execution and unittest discovery resolve
  active modules consistently. Use `py tests/run.py` for the full suite.
- Put current instructions in `docs/`. Root-level commands in the guides assume
  the project root unless they use an absolute path.
- Put completed one-off investigations and replaced implementations in `archive/`.
  Historical commands there may reference old locations or deployed binaries.

## Stable state and evidence

`headless/local_service.py` provides a small standard-library HTTP transport bound
to `127.0.0.1`, with explicit routes and same-origin/token checks for writes. It
contains no match, database or game logic. `match_review_service.py` registers the
review routes; `match_adjudication.py` owns validation and transactional SQLite
decision/rating updates. Extend the route layer for future local functionality
without coupling it to the recorder. `review --serve` runs one foreground process
until Ctrl+C, using an OS-selected free port. There is no daemon manager, external
web framework or periodic background refresh.

`data/rankbot.sqlite3`, `data/friends_control.sqlite3`, and controller locks retain
their locations. Existing `validation/` directories are intentionally retained:
databases, experiment manifests, saved commands and documentation reference them.
Do not bulk-move evidence without migrating those references. Old database backup
files are now under `archive/backups/`; live databases were not relocated.

`tools/` contains external debuggers. `.venv-report/` is a local reporting environment;
its directory is retained because virtual environments embed their installation paths.
Generated bytecode and local environments are ignored by Git.

## Reorganization record

[Move manifest](../archive/reorganization/moves.json) records original and final
locations. [Original editable files](../archive/reorganization/originals/) preserve
the pre-reorganization sources and configuration. No game-install files were moved.
The previous root README and VS Code configuration are in that snapshot.

The count override remains removed. The restructuring changes source locations,
imports, documentation and test setup; it does not add game actions or enable
experimental memory cleanup in automatic or record-only hosting.
